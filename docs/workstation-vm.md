# Workstation VM: Ubuntu in UTM on the Mac

An optional Linux workstation for the lab: an Ubuntu Server virtual machine (VM) in UTM on an Apple Silicon Mac. You edit code, run `terraform fmt` and `validate`, run Conftest, and push branches from it. GitHub Actions still runs every plan and apply. Built and tested 2026-10-23.

Two ways to put the tools on it:
- **[tool-install.md, Linux section](tool-install.md#linux-debian-or-ubuntu):** the standard path. Tools go into `lab-tools/` inside the repo, no `sudo` for the tools, opt-in `PATH` per terminal. Includes SailPoint CLI.
- **[scripts/bootstrap-iac-lab-vm.sh](../scripts/bootstrap-iac-lab-vm.sh):** a one-shot script for a dedicated VM. Same pinned versions, installed system-wide in `/usr/local/bin`, plus VM hardening (firewall, automatic security updates). Skips SailPoint CLI and Microsoft365DSC. Use it when the VM exists only for this lab.

Pick one per machine. If a pinned version changes, change it in both places in the same commit.

## 1. Decisions

| Item | Value | Why |
|---|---|---|
| Role | Workstation only | Plan and apply stay in GitHub Actions, which sign in to Azure through OIDC (OpenID Connect) federation. The VM never needs Azure or Okta credentials. |
| OS (operating system) | Ubuntu Server 24.04 LTS (Long Term Support), arm64 | Same release as the GitHub Actions runners. 26.04 LTS was skipped: Microsoft's Azure CLI apt suite for 26.04 (`resolute`) was published empty in August 2026 and arm64 was unconfirmed ([runner-images issue 14647](https://github.com/actions/runner-images/issues/14647)). Revisit when it ships. |
| Hypervisor | UTM, **Virtualize** (QEMU engine, the UTM default), not Emulate | Native Arm speed |
| Hostname / user | `iac-lab-ubu01` / `iac-lab` | Follows the `iac` prefix; not a personal name or `admin` |
| Memory / CPU | 4 GB minimum, 6 to 8 GB recommended; 4 cores | Terraform, Azure CLI and PowerShell together are slow at 4 GB |
| Network | UTM **Shared Network** (NAT, network address translation) | The Mac can reach the VM (a `192.168.64.x` address); the home network cannot |
| Shared folder | None | The VM cannot read or write Mac files |
| Repo | Fresh HTTPS (Hypertext Transfer Protocol Secure) clone with a fine-grained token | See section 5 |

## 2. Create the VM in UTM

1. Download the installer: ubuntu.com/download/server/arm, file `ubuntu-24.04.x-live-server-arm64.iso`. **Not** a `.7z` file from the UTM Gallery: those are prebuilt VM archives, the firmware cannot boot them, and the VM lands at a `Shell>` prompt (the UEFI (Unified Extensible Firmware Interface) shell). The gallery's Ubuntu 18.04 image is also past end of support.
2. UTM > **+** > **Virtualize** > **Linux**. Leave "Use Apple Virtualization" unchecked. Boot from ISO image > **Browse** > the ISO.
3. Memory and CPU from the table above. Disk 64 GB. No shared directory. Name `iac-lab-ubu01`.
4. Before first boot: Edit > Network > Network Mode = **Shared Network**.
5. Boot > **Try or Install Ubuntu Server**.

## 3. Installer choices

- Regular Ubuntu Server (not minimized). Network: DHCP (Dynamic Host Configuration Protocol). Proxy blank, default mirror.
- Storage: entire disk, LVM (Logical Volume Manager). Disk encryption optional; the Mac disk is already FileVault-encrypted.
- Profile: server name `iac-lab-ubu01`, username `iac-lab`, password generated by your password manager.
- **Install OpenSSH server**: checked. Do not import a key here.
- No featured snaps. Reboot. If it boots the installer again: stop the VM, CD/DVD > **Clear**, start.
- Check: `iac-lab-ubu01 login:` prompt, then `ip -4 addr` shows `192.168.64.x`.

## 4. SSH with a key held in 1Password

SSH (Secure Shell) logins use a key that never touches the Mac disk.

1. **Key:** 1Password > the lab vault > New Item > SSH Key > Add Private Key > Generate New Key > Ed25519. Title `iac-lab-ubu01`.
2. **Agent on:** 1Password > Settings > Developer > **Use the SSH Agent**. Settings > General > **Keep 1Password in the menu bar** and **Start at login**.
3. **Allow the lab vault.** By default the agent only offers keys in the Personal (or Private) vault. A key in any other vault is invisible until named in `~/.config/1Password/ssh/agent.toml`. This file also limits the agent to this one key:
   ```toml
   [[ssh-keys]]
   item = "iac-lab-ubu01"
   vault = "<lab vault name>"
   ```
4. **Public key to disk:** open the item > public key field > **Download** > save as `~/.ssh/iac-lab-ubu01.pub`. Not a secret.
5. **`~/.ssh/config`** (type it or use a here-document; a stray character after `IdentitiesOnly yes` stops SSH with "bad configuration options"):
   ```
   Host iac-lab-ubu01
     HostName 192.168.64.X
     User iac-lab
     IdentityAgent "~/Library/Group Containers/2BUA8C4S2C.com.1password/t/agent.sock"
     IdentityFile ~/.ssh/iac-lab-ubu01.pub
     IdentitiesOnly yes
   ```
   `chmod 600 ~/.ssh/config`. Check with `ssh -G iac-lab-ubu01 | grep -Ei '^(hostname|user|identitiesonly) '`. `IdentitiesOnly yes` stops the agent offering other keys, which avoids "Too many authentication failures" (servers allow about six attempts).
6. **Agent check:** `SSH_AUTH_SOCK=~/Library/Group\ Containers/2BUA8C4S2C.com.1password/t/agent.sock ssh-add -l` lists one key.
7. **Install the key on the VM.** `-f` is required: `ssh-copy-id` otherwise refuses because no private key file sits next to the `.pub`.
   ```bash
   ssh-copy-id -f -i ~/.ssh/iac-lab-ubu01.pub iac-lab-ubu01   # VM password, once
   ssh iac-lab-ubu01                                          # 1Password approval, no password
   ```
8. **Keys only.** Any `sudo` over SSH needs `ssh -t`, or `sudo` cannot ask for the password:
   ```bash
   ssh -t iac-lab-ubu01 'echo -e "PasswordAuthentication no\nKbdInteractiveAuthentication no\nPermitRootLogin no\nAllowUsers iac-lab" | sudo tee /etc/ssh/sshd_config.d/10-iac-lab.conf && sudo systemctl restart ssh'
   ssh -t iac-lab-ubu01 'sudo sshd -T | grep -E "^(passwordauthentication|permitrootlogin|allowusers) "'
   ```
   Expect `passwordauthentication no`, `permitrootlogin no`, `allowusers iac-lab`. Keep the UTM console open until this works.

## 5. Tools and repo

**Script path:**
```bash
scp scripts/bootstrap-iac-lab-vm.sh iac-lab-ubu01:
ssh -t iac-lab-ubu01 'bash bootstrap-iac-lab-vm.sh'
ssh -t iac-lab-ubu01 'sudo reboot'     # the script's package upgrades want one
```
Tested 2026-10-23 on Ubuntu 24.04 arm64 in UTM: Terraform 1.16.4, Azure CLI 2.90.0, PowerShell 7.6.6, Conftest 0.71.0, Node 24.21.0, Prism 5.16.0, gh 2.103.0. The PowerShell checksum step was changed after that run to handle a UTF-16 hashes file (see [tool-install.md](tool-install.md#step-3-pinned-tools-no-sudo)); UNVERIFIED: the changed step has not been re-run on a clean VM.

**Or the standard path:** clone first, then tool-install.md Linux steps 2 to 4 inside the VM.

**Clone with a fine-grained token.** Make a fine-grained PAT (personal access token) at github.com/settings/personal-access-tokens/new:
- Name `iac-lab-ubu01`, expiry 30 days, resource owner the lab org.
- Repository access: only this repo. Permissions: Contents and Pull requests, Read and write (Metadata Read is automatic).
- Record it in [permission-register.md](permission-register.md) with its expiry.

```bash
git config --global user.name "<name>"
git config --global user.email "<id+user>@users.noreply.github.com"
git config --global credential.helper 'cache --timeout=28800'   # the script sets this; token held in memory 8 hours, never on disk
mkdir -p ~/Projects && cd ~/Projects
git clone https://github.com/<github-org>/<repo>.git okta-to-entra-migration
cd okta-to-entra-migration && terraform fmt -check -recursive
```
Username: your GitHub username. Password: the token.

## 6. Access decisions

| Credential | On the VM | Not this |
|---|---|---|
| GitHub | Fine-grained PAT, one repo, Contents and Pull requests write, 30 days, memory-only cache | `gh auth login`: OAuth (Open Authorization) `repo` scope over every repo you can reach, token in plaintext `~/.config/gh/hosts.yml` |
| Azure | None; plans run in PR (pull request) checks | `az login` as the subscription Owner and Global Administrator |
| Okta | None; the reader key stays in `~/.okta-lab/` on the Mac | Copying the key or an SSWS (Okta API) token to the VM |
| SSH | Ed25519 key in 1Password, password logins off, `AllowUsers`, NAT only | Password SSH on a home-network address |

If the VM is compromised (a bad npm package, a prompt-injected agent), it can push branches to one repo, and branch protection plus the second reviewer still gate `main`. Cost of the narrow version: about 5 minutes to make the token, one paste per 8-hour session, monthly renewal.

Revisit if: you want local `terraform plan` (use a dedicated read-only lab user with Reader on `rg-iac-lab` and Entra Global Reader, signed in with `az login --use-device-code`), or the VM becomes a self-hosted Actions runner (separate OS user, OIDC-only Azure identity, runner registered to this repo only).

## 7. Rollback point

Shut down (`ssh -t iac-lab-ubu01 'sudo poweroff'`), then in UTM right-click the VM > **Clone** > `iac-lab-ubu01-baseline`. UTM has no snapshot button; a stopped clone is the rollback.
